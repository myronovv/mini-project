# Звіт

## Агент виявлення аномалій у енергомережі

| Параметр | Значення |
|----------|----------|
| **Дисципліна** | Створення агента ШІ для автоматизації процесів |
| **Тематичний блок** | Автоматизація енергосистем |
| **Обраний варіант** | **10** — Агент виявлення аномалій у мережі |
| **Метод** | Autoencoder (нейромережева реконструкція) |
| **Назва агента** | Network Anomaly Detection Agent |
| **Середовище** | Python 3, PyTorch, Streamlit (локально, **без зовнішніх API**) |

---

## 1. Мета роботи

Розробити інтелектуального агента, який автоматично аналізує показники сенсорів енергомережі, виявляє **аварійні та передаварійні стани** та формує **рішення** для оператора (рівень тривоги + рекомендовані дії).

Агент має працювати як завершена система з джерелом даних, pipeline обробки, моделлю машинного навчання, агентною політикою, інтерфейсом користувача та метриками якості — відповідно до структури завдання з методичних матеріалів.

---

## 2. Постановка задачі (варіант 10)

Згідно з завданням, **варіант 10** передбачає:

- **Об'єкт:** енергомережа (показники вузлів / ліній / трансформаторів).
- **Задача:** виявлення аварійних станів (аномалій) у потоку даних.
- **Рекомендований метод:** **autoencoder** — модель навчається відтворювати «нормальний» режим роботи; для аномальних записів помилка реконструкції зростає.

Обмеження реалізації: система працює **автономно на локальному комп'ютері**, без підключення до зовнішніх API (погода, LLM, хмарні сервіси).

---

## 3. Загальна архітектура системи

```
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  CSV-дані       │────▶│  Data Pipeline   │────▶│  Autoencoder    │
│  (сенсори)      │     │  (нормалізація)  │     │  (PyTorch)      │
└─────────────────┘     └──────────────────┘     └────────┬────────┘
                                                          │
                                                          ▼
┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  Streamlit UI   │◀────│  Network Agent   │◀────│  Помилка        │
│  (app.py)       │     │  (політика)      │     │  реконструкції  │
└─────────────────┘     └──────────────────┘     └─────────────────┘
```

**Етапи роботи агента:**

1. Зчитування хвилинних вимірів сенсорів.
2. Нормалізація ознак (StandardScaler).
3. Прогін через навчений autoencoder → обчислення MSE реконструкції.
4. Порівняння з порогом → бінарна ознака «аномалія».
5. Класифікація рівня тривоги та генерація текстової рекомендації.

## 4. Джерела даних

### 4.1. Тип даних

Використано **синтетичні** часові ряди, що імітують роботу енергомережі. Це допустимо згідно з методичкою («реальні або синтетичні» дані).

Генератор: `src/data_generator.py`

### 4.2. Ознаки (сенсори)

| Стовпець | Одиниця | Опис |
|----------|---------|------|
| `timestamp` | дата/час | Мітка часу виміру |
| `voltage_kv` | кВ | Напруга в мережі |
| `current_a` | А | Струм |
| `frequency_hz` | Гц | Частота |
| `active_power_mw` | МВт | Активна потужність |
| `reactive_power_mvar` | Мвар | Реактивна потужність |
| `transformer_temp_c` | °C | Температура трансформатора |
| `line_load_pct` | % | Завантаження лінії |

### 4.3. Набори даних

| Файл | Призначення | Записів (типово) |
|------|-------------|------------------|
| `data/train_normal.csv` | Навчання autoencoder (лише нормальний режим) | 8000 |
| `data/test_with_anomalies.csv` | Тестування та оцінка метрик | 2000 |

### 4.4. Типи штучних аномалій у тесті

| Тип (`anomaly_type`) | Опис |
|----------------------|------|
| `voltage_sag` | Просідання напруги, зростання струму |
| `frequency_drift` | Відхилення частоти від 50 Гц |
| `overload` | Перевантаження лінії, перегрів |
| `thermal_fault` | Різке підвищення температури трансформатора |

Мітки для оцінки: `is_anomaly` (0/1), `anomaly_type` (текст).

## 5. Pipeline обробки даних

**Модуль:** `src/pipeline.py`

| Крок | Дія |
|------|-----|
| 1 | Завантаження CSV (`pandas`) |
| 2 | Вибір числових ознак з `FEATURE_COLUMNS` |
| 3 | Нормалізація **StandardScaler** (fit на train, transform на test) |
| 4 | Збереження scaler у `models/scaler.joblib` для повторного використання |

Pipeline гарантує, що модель отримує дані в однаковому масштабі при навчанні та під час роботи агента в інтерфейсі.

---

## 6. Модель машинного навчання (Autoencoder)

**Модуль:** `src/model.py`

### 6.1. Ідея методу

Autoencoder складається з **кодувальника** (encoder) і **декодувальника** (decoder). Модель навчається мінімізувати помилку відтворення вхідного вектора ознак.

- На **нормальних** даних помилка низька.
- На **аномальних** (які модель «не бачила») помилка реконструкції **зростає**.

Таким чином аномалія виявляється **без явної розмітки під час експлуатації** — потрібні лише «здорові» дані для навчання.

### 6.2. Архітектура мережі

| Параметр | Значення |
|----------|----------|
| Вхід | 7 ознак |
| Приховані шари encoder | 32 → 16 |
| Латентний простір | 8 нейронів |
| Функція втрат | MSE (Mean Squared Error) |
| Оптимізатор | Adam |
| Поріг аномалії | 95-й перцентиль помилки на train |

### 6.3. Збереження моделі

Після навчання зберігаються:

- `models/autoencoder.pt` — ваги мережі
- `models/meta.json` — поріг, розмірність входу
- `models/scaler.joblib` — об'єкт нормалізації

## 7. Агентна логіка (policy / decision-making)

**Модуль:** `src/agent.py`  
**Клас:** `NetworkAnomalyAgent`

Агент — це не лише модель, а **шар прийняття рішень** поверх неї.

### 7.1. Виявлення аномалії

```
якщо MSE_реконструкції > порогу  →  is_anomaly = True
```

### 7.2. Рівні тривоги

| Рівень | Умова | Зміст |
|--------|-------|-------|
| **НОРМА** | помилка ≤ порогу | Штатний режим |
| **ПОПЕРЕДЖЕННЯ** | поріг < помилка < 2.5× порогу | Потенційна проблема |
| **АВАРІЙНИЙ СТАН** | помилка ≥ 2.5× порогу | Критична ситуація |

### 7.3. Пояснення та рекомендації

Агент аналізує сирі значення сенсорів і формує **підказку** (наприклад, «просідання напруги», «перевантаження лінії») та **текст дії** для оператора:

- *НОРМА* — продовжити моніторинг.
- *ПОПЕРЕДЖЕННЯ* — посилити контроль, підготувати втручання.
- *АВАРІЙНИЙ СТАН* — негайне сповіщення диспетчера, ізоляція ділянки, зниження навантаження.

Це відповідає вимозі методички щодо **агентної логіки (policy / decision-making)**.

## 9. Метрики якості

**Модуль:** `src/metrics.py`  
**Результати:** `reports/evaluation.json`

| Метрика | Опис |
|---------|------|
| **Accuracy** | Частка правильних класифікацій (аномалія / норма) |
| **Precision** | Точність серед спрацювань «аномалія» |
| **Recall** | Частка виявлених справжніх аномалій |
| **F1-score** | Гармонійне середнє precision і recall |
| **Latency** | Середній час інференсу на один запис (мс) |
| **Confusion matrix** | Матриця помилок (TN, FP, FN, TP) |

### 9.1. Приклад результатів (після навчання)

Типові значення на тестовому наборі:

| Метрика | Значення |
|---------|----------|
| Accuracy | ~0.95 |
| Precision | ~0.54 |
| Recall | 1.00 |
| F1 | ~0.70 |
| Latency | < 0.001 мс / запис |

**Інтерпретація:** агент виявляє **усі** справжні аномалії (recall = 1), але частина нормальних записів може помилково позначатися як аномалія (нижча precision). Для систем безпеки енергомережі це прийнятний компроміс; поріг можна налаштувати.

## 14. Висновки

1. Реалізовано **AI-агента виявлення аномалій у енергомережі** відповідно до **варіанту 10**.
2. Застосовано метод **autoencoder**: модель навчається на нормальному режимі та виявляє відхилення за помилкою реконструкції.
3. Реалізовано повний цикл: **дані → pipeline → модель → агентні рішення → інтерфейс → метрики**.
4. Веб-інтерфейс Streamlit дозволяє наочно продемонструвати роботу агента на захисті роботи.
